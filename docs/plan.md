# Hearthside: Project Plan v1.0 (Offline Release Ready)

Version 1.0, November 27, 2026. Status legend: **Confirmed** means locked by the project owner; **Proposed** means recommended default awaiting confirmation if changes are needed; **Open** means unresolved.

Version 1.0 completes **Phase 3 (Polish and 1.0)**: reduced-motion-safe Sudoku micro-interactions, refined Web Audio SFX + `unitComplete` cue, procedural per-theme ambient music (D24), automated WCAG 2.1 AA audits across all 4 theme×mode variants (`@axe-core/playwright`), focus trapping & keyboard playability, dynamic `<meta name="theme-color">`, lazy chunk splitting, and `v1.0.0` release verification ahead of Phase 4 backend services.

## 1. Vision and scope

Hearthside is a free, family-focused, all-in-one game app that grows over time to tens of puzzle and card games, including real-time and multiplayer ones. Sudoku is first. It must work offline, look polished in high definition, and run on Windows, Linux, Android (phone and tablet) and in the browser as a PWA.

Non-goals (Confirmed): monetization, app-store publishing, user analytics, Apple platforms, RPG-style games.

## 2. Confirmed requirements

### 2.1 Platforms and access

- Windows, Linux, Android phone and tablet, and browser/PWA.
- Offline play is required.
- Support the latest couple of OS and browser versions; the floor follows from the family devices below and is verified on each one in Phase 0.
- English (US) only; dark mode wanted.
- Family devices and OS mapping:
  - Desktop (Windows 11) and Alienware 16 laptop (Windows 11), with a 32-inch Samsung Odyssey Neo G7 monitor.
  - Dell XPS 15 laptop (Windows 10).
  - Home server (Ubuntu).
  - Samsung Galaxy Tab S9 and Tab S10 FE (Android).
  - Pixel 6 Pro and Pixel 9 (Android 17+).

### 2.2 Sudoku gameplay

- Easy, medium and hard, defined by the solving techniques a puzzle requires. Section 6.3 holds the starting tiers, to be refined after playtesting.
- Puzzles generated by the backend (and deterministically via the same Go engine in WASM when offline), each with a guaranteed unique solution.
- Per-square annotations (candidate notes), editable by the player.
- Selecting any square, filled or empty, highlights its 3x3 box, row and column. Squares holding the same number also highlight.
- Mistake checking uses two independent per-profile toggles: flagging duplicate peer conflicts (default ON) and a separate kid-friendly toggle for flagging entries that do not match the unique solution (default OFF), plus an on-demand Check Board action and no 3-strike game-over (D21).
- Placing a number removes it from view in the notes of affected squares, even when auto-show is off. If the entry is cleared or undone, those notes return.
- Auto-show toggle: displays computed candidates for empty squares. Turning it on overwrites the displayed notes while the player's manual notes are kept in memory. Turning it off restores the manual notes. Notes stay editable while it is on, and edits persist across neighbor changes until auto-show is turned off (D12, D20).
- Undo/redo, hints, mistake checking, timer and pause, save and resume, stats, daily puzzle and themes are all part of the launch-quality game.
- Input: touch, stylus (Pointer Events), and mouse. Keyboard navigation is included for accessibility; gamepad support is expected for later games.

### 2.3 Platform services

- Wanted: accounts, cloud save, daily puzzles and leaderboards, delivered in follow-on phases (Phases 4 to 7 and 9) after an offline-first 1.0. Offline mode must keep working without them.
- The backend is private and invite-only for the family, hosted on the Ubuntu home server behind Traefik with HTTPS (`hearthside.example.com`), internal-only initially and exposed externally when ready.
- Email addresses are acceptable, and Google sign-in is an option (already used for Immich). Child profiles sit under a parent's household account, and parents and children can play together: a shared household view of leaderboards and daily results, same-device play with profile switching, and live co-op or head-to-head play on one puzzle across devices (D14).

### 2.4 Quality and content

- High-definition, polished, professional-looking visuals.
- Themes: clean/minimal plus other styles, at least for some games.
- Optional sound and music.
- Assets are free or AI-generated, using what Google AI Pro provides plus free tools on Ubuntu.

### 2.5 Privacy and audience

- No user analytics.
- Children are part of the target audience.

### 2.6 Resources

- Solo developer using Google Antigravity for implementation; no budget beyond AI subscriptions; no fixed deadline, so progress follows exit criteria, not dates.

**D20. Auto-show candidate edits when neighbors change (confirmed).** While auto-show is ON, manual candidate edits are tracked per cell as `autoShowExcluded` and `autoShowAdded` bitmasks layered over `computedCandidates`. Toggling auto-show OFF discards the overlay and restores `manualNotes` untouched.

**D21. Mistake checking settings (confirmed).** Mistake checking is split into two independent per-profile boolean toggles, with no 3-strike game-over:
- **Flag duplicate conflicts** (default ON): highlights cells when two or more cells in the same row, column, or 3x3 box share a digit.
- **Flag wrong values (kid-friendly)** (default OFF): highlights entries that do not match the puzzle's unique solution even when no peer duplicate exists.
- An on-demand **Check Board** action is available regardless of live toggle settings. If a player requests a hint while an unflagged wrong value is on the board, the hint flow alerts them to the wrong entry first rather than giving a misleading logical step.

**D22. Offline daily puzzles (confirmed).** Before Phase 4 introduces the server daily schedule, Daily Puzzles are generated deterministically via WASM from `(YYYY-MM-DD, difficulty, engineVersion)` so every family device gets the exact same Daily Puzzle offline. Regular play draws from the bundled 150-puzzle starter bank and tops up via WASM when a tier's bank is exhausted.

**D23. Local profiles in offline v1 (confirmed).** Lightweight same-device profiles consisting of a display name and preset avatar icon/color (no PIN required in offline v1). Each profile isolates in-progress games, stats, theme/mode selection, and gameplay settings (including D21 toggles), with a quick switcher in the shell header.

**D24. Audio rollout (confirmed).** Phase 2 built the full Web Audio service (independent SFX and Music mute/volume toggles persisted per profile, unlocked on first pointer or keyboard gesture) with synthesized SFX cues. Phase 3 delivers **procedural Web Audio ambient music** tailored per theme (**Clean Minimal**: airy crystalline pentatonic/major-7th tones; **Warm Hearthside**: cozy low-passed felt-piano / mellow chord progressions) for v1.0, requiring zero external audio files or network fetches. Playback uses click-free linear/target envelopes (~150–300ms fades, never `exponentialRampToValueAtTime(0, ...)`), respects browser autoplay policy, crossfades smoothly on live theme changes, and pauses/resumes automatically on `document.visibilitychange`, while keeping the `MusicChannel` interface extensible for future file-backed `.ogg`/`.mp3` tracks without changing the Settings UI.

## 4. Architecture

### 4.1 Client: PWA first

One TypeScript codebase delivers Windows, Linux, Android phone/tablet and browser through an installable PWA. It works offline through a service worker and IndexedDB, needs no app store, and scales to any resolution because the UI is vector-based. Thin wrappers such as Tauri (desktop) or Capacitor (Android) remain optional only if the PWA falls short on a supported device.

- Package manager / runtime: Bun (v1.4.5+) (D18).
- Language and build: TypeScript (strict), Vite.
- UI: React (D17).
- Rendering: DOM/SVG for the Sudoku board; a canvas library such as PixiJS for card and real-time games.
- Browser APIs: Pointer Events, Keyboard, Gamepad (later games), WebSocket (multiplayer), Web Audio, Web Worker (WASM).

### 4.2 Repository layout (monorepo)

- `AGENTS.md` and `.agents/rules/*.md`: Google Antigravity workspace instructions and scoped rules.
- `apps/web/`: the PWA shell.
- `packages/game-core/`: platform-agnostic game framework and the game plugin interface.
- `packages/ui/`: design system, tokens, themes, shared components.
- `games/sudoku/`: Sudoku UI, pure reducer, starter bank, and WASM worker adapter; later games get sibling folders.
- `engine/sudoku/`: Go module — solver, generator and grader, shared by backend and WASM.
- `services/api/`: Go module — backend (Phase 4+).
- `assets/`: art, audio, fonts, and `manifest.json`.
- `deploy/`: Dockerfile, nginx config, and Docker Compose with Traefik labels.
- `docs/`: `plan.md`, `decisions/` (ADRs), `assets/` (tool inventory).
- `.github/workflows/`: CI.

### 4.3 Game plugin interface

Each game provides: metadata, a serializable state schema, pure rules (a deterministic reducer), a UI component, input mappings, save/restore, and optional multiplayer and AI adapters. The shell provides profiles, settings, themes, audio, storage, sync, stats and leaderboards. Because game state changes through an event log, undo/redo, save/resume, replays and later authoritative multiplayer all come from the same mechanism.

### 4.4 Backend (Go)

- Service: Go standard library or a small router; REST/JSON plus WebSocket for real-time.
- Storage: SQLite to start (family scale), with migrations; moving to Postgres stays possible.
- Auth: invite-only household accounts with email or Google sign-in (OpenID Connect); child profiles sit under a parent's household account (D9). Offline play never requires sign-in.
- Puzzle service: puzzle bank, difficulty grading, daily schedule.
- Sync: versioned per-game save blobs; stats merged from event logs; conflict rule agreed before Phase 5 builds it.
- Leaderboards: per puzzle and per day; the server re-validates submitted solutions.
- Multiplayer (later): authoritative Go game server over WebSockets with rooms.
- Operations: runs on the Ubuntu home server with Docker Compose behind Traefik and HTTPS (D10, D16), rate limiting, backups with a tested restore, privacy-respecting logs, no analytics.

## 5. Sudoku engine (Go)

- Board model: 81 cells, each with a value, a given flag and a 9-bit notes mask.
- Solver: a logical solver applies techniques in order of difficulty and records every step; a separate backtracking solver counts solutions to prove uniqueness.
- Generator: seeded and deterministic. Build a full grid, remove clues, verify exactly one solution, grade, and accept only if the grade matches the target tier. The same seed and engine version always give the same puzzle, which makes daily puzzles reproducible.
- Puzzle record: id, seed, engine version, difficulty, techniques required, clues, solution.
- Puzzles that need guessing are rejected.

## 6. Sudoku game design

### 6.1 Notes and auto-show (Confirmed)

Each cell stores `manualNotes` separately from `computedCandidates` and the active auto-show overlay (`autoShowExcluded` / `autoShowAdded`, D20). A note digit is hidden, never deleted, while any cell in its row, column or box holds that digit; clearing or undoing that entry brings the note back. Displayed notes are `manualNotes & ~peerPlacedMask` when auto-show is off, and `((computedCandidates | autoShowAdded) & ~autoShowExcluded) & ~peerPlacedMask` when auto-show is on. Turning auto-show on keeps `manualNotes` untouched in memory; turning it off discards the overlay and restores `manualNotes` (D12, D20).

### 6.2 Highlighting (Confirmed)

Select any cell: highlight its 3x3 box, row and column. Also highlight same-valued cells. Duplicate conflicts are flagged when the per-profile "Flag duplicate conflicts" setting is enabled (default ON, D21).

### 6.3 Difficulty by technique (Confirmed starting point; refine after playtesting)

- Easy: naked and hidden singles.
- Medium: adds pointing pairs/triples, box-line reduction (claiming), naked/hidden pairs, and naked/hidden triples.
- Hard: adds Skyscraper, X-Wing, W-Wing, XY-Wing, and Swordfish.

A puzzle's tier is the hardest technique it needs. Tiers are tuned by playtesting in Phase 3.

### 6.4 Feature specs (Confirmed for Phase 2)

- Undo/redo: unlimited, via the event log.
- Hints: 4-tier progressive hints based on the current board (1: highlight target region, 2: name technique, 3: highlight driving cells & eliminations, 4: apply/reveal step). Alerts the player if an unflagged wrong entry exists before giving a logical hint.
- Mistake checking: two separate per-profile toggles — *Flag duplicate conflicts* (default ON) and *Flag wrong values (kid-friendly)* (default OFF) — plus an on-demand *Check Board* button and no 3-strike game-over (D21).
- Timer and pause: pausing stops the timer and conceals board digits.
- Save and resume: automatic per profile in IndexedDB, supporting one in-progress game per difficulty plus the active Daily Puzzle.
- Stats: per profile — games started and won, best and average time by difficulty, current/best daily streaks, hint usage.
- Themes: Clean Minimal and Warm Hearthside, each with Light and Dark modes (per-profile preference).
- Sound: independent SFX and Music mute/volume toggles; refined Web Audio synthesized SFX (including completed-unit celebration) and procedural per-theme ambient music in Phase 3 behind an extensible `MusicChannel` interface (D24).

### 6.5 Input (Confirmed)

Pointer Events (touch, S Pen/stylus, mouse): tap or click a cell, then a number pad; notes-mode toggle; auto-show toggle; erase. Full keyboard navigation (arrows, `1–9`, `Backspace`/`Delete`, `N` for notes, `Ctrl+Z`/`Ctrl+Y`) included for accessibility.

## 7. Visual design and assets

- Design tokens for color, type, spacing and motion; each theme is a token set, with light and dark variants.
- Vector first (SVG and CSS); raster only for illustrations and backgrounds, in multiple densities or modern formats. Targets: phones, tablets and desktop up to 4K, tested at 1x to 3x pixel density.
- Kid-friendly baseline: large touch targets (>= 44x44px), simple wording, no ads, no external links, no chat or free-text sharing in v1.
- Accessibility baseline: WCAG 2.1 AA contrast, state never conveyed by color alone, reduced-motion support, scalable text.
- Free and AI-generated assets carry license risk. `assets/manifest.json` records provenance (enforced by automated test) and must be audited before sharing beyond the household.

## 12. Phase 1 in detail (Completed)

### 12.1–12.6 Summary of deliverables

- **Puzzle-bank CLI (`12.5`):** `engine/sudoku/cmd/genbank` generated and verified the 150-puzzle starter bank (`games/sudoku/src/data/starter-bank.json`, 50 per tier).
- **Production WASM bridge (`12.6`):** Rebuilt via `scripts/build-wasm.sh` (Go 1.27.4): `sudoku-go.wasm` is 4.38 MiB raw (under 10 MiB Workbox cap) and 1.20 MiB gzip-9 (well under the 2.00 MiB budget).
